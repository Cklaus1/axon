# CVM — canonical-history working-set projections

**Owners:** CX-28 working sets; CX-10 canonical evidence; CX-02 observations. **Tasks:** B239/B240/B245. **Reference:** RES-CLIFF.

CVM is a readable alias for the existing Semantic Working-Set Manager, not a new Context Lifecycle Manager service. CLM elsewhere in this pack always means Contrastive Language Models.

## Canonical versus active state

Keep canonical events/artifacts under existing retention and permission owners. A working prompt is a disposable, versioned projection of authorized originals. It may contain selected original segments and explicitly identified derived summaries, but a previous compaction is never the new canonical source for another compaction. Rebuild from originals and stable artifact references.

Record source snapshot/event IDs and content digests, policy/tokenizer/model revision, selected and excluded ranges, derived material, total token count, mandatory pins and closure dependencies. Canonical integrity uses the existing recording/audit infrastructure. A local list and a hash alone are not a durable or independently anchored journal.

Retention may legitimately remove data. A tombstone or unavailable reference is not permission to resurrect deleted private content from an embedding cache. Record incomplete reconstruction; do not claim immortal event availability or complete summaries when originals have expired.

## Selection and pinning

Pins include current task requirements, grants/constraints as references to authority, active obligations, relevant negative outcomes, current plan state, unresolved actions and complete tool-call/result dependencies. Preserve the distinction between data quoted from a tool and trusted host instructions. A compacted prompt cannot redefine actual permissions.

Measure tokens with the consuming model's tokenizer and reserve required output/tool overhead. Select dependency closures, not independent chunks that orphan tool results. If pins plus their closure exceed budget, block/escalate to a qualified larger-context path or ask the host to restructure; never quietly delete the constraints. Character limits are not token budgets.

Cliff-inspired dropping/truncating policies are candidate arms. Do not inherit arbitrary dropping of images or long tool results where that erases required evidence. Preserve canonical bytes and retrieval handles; evaluate critical-evidence recall and resulting final task outcomes.

## Prefix and failure behavior

Stable prefix identity supports a cheap reconstruction path. When an upstream scaffold rewrites history or prefix matching fails, recompute from authorized original events using the current policy or return explicit refusal. “Fail open” must not mean forward an oversized request, lose pinned constraints or fabricate a complete history. Retry on context-window error is bounded and separately charged.

Do not run upstream proxy installers, edit shell startup files, start background services or change global model endpoints as part of importing this pack. A qualified proxy, when chosen, is explicitly configured per worker and can be disabled independently. Shadow mode compares projections without changing incumbent behavior first.

## Evaluation

Use full-context/no-compaction and incumbent policies as controls at feasible budgets. Include long coding sessions, repeated compaction, rewritten prefixes, unavailable originals, cancelled tools, interleaved concurrent actions, image-dependent requirements and prompts designed to bury constraints. Measure preserved critical facts, tool-pair closure, reconstruction fidelity, prompt cost/cache behavior and independent task success. Lower input tokens alone are not a win if extra turns or mistakes cost more.

A learned context scorer is optional. It never owns deletion, retention or authority, and its candidate-specific scores do not authorize hiding inconvenient negative evidence from an evaluator.
