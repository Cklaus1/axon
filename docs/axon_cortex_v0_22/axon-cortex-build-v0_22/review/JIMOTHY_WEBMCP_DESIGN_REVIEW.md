# Jimothy / WebMCP integration — design review folded into v0.20 / v0.14

**Review scope:** supplied v0.19/v0.13 source packs, the supplied integration review and prior connector-source observations; static document/contract review and model-free executable reference/mutation tests. This is not a third-party security audit, fresh upstream survey, trained-model benchmark or live product review.

## Accepted integration

The amendment implements a bounded schema/frontend profile and an explicit lightweight fixed-task training/evaluation profile as **proposed build requirements** under existing owners. It adds model-free reference code and fixtures, owner/consumer crosswalks, dependency-ordered work packages and product gates. The new paths preserve source and artifact identity, external authority, independent evidence and exact profile qualification.

No new Reflex engine, .reflex format, universal compiler IR or admission authority was introduced. CX-36 r0.2 source/container/schema files remain byte-identical to the input Axon v0.19 pack; ACE v1 wire schemas are also unchanged. A learned Reflex can use .np; deterministic/TF-IDF representations do not become neural merely because they share a training workflow. Schema lowering does not itself create trained weights or an admitted program.

## Decisions and rationale

| Finding | Folded-in resolution | Remaining product evidence |
|---|---|---|
| Earlier prose opposed Reflex to deterministic .np and called schema lowering a neural compiler | Explicitly preserve existing CX-23/CX-36 ownership and distinguish schema plans from learned candidates | Real artifact/compiler/consumer mappings |
| Fixed-question head treated as arbitrary dynamic tool router | Frozen task/label/input identity; dynamic options require qualified candidate-conditioned model or retraining | Coding/task-domain applicability and OOD |
| Missing Boolean/presence could become confident false/absence | Active-output failure first; complete typed invocation checked before proposal | Actual provider decoder/use-site conformance |
| Minimum/product confidence presented as joint correctness | Marginals are diagnostic; separate named reference, complete-invocation and verified-outcome events | Empirical calibration on deployment population |
| Broad schema support implied from a small demo | Bounded closed scalar subset; reject arrays/nesting/unions/refs/unknown constraints; extensions optional | Actual MCP/WebMCP adapter protocol compatibility |
| Teacher labels or approval treated as truth | Authentication/adjudication, explicit label kinds, exact joins and protected role-scoped caches | Real data governance and label audits |
| Calibration quality could be overstated by small/correlated samples | Disjoint data roles, exact corrected finite-grid bounds, independent representatives, critical-class support and null cutoffs | Independent representative final evaluation |
| Shared encoders could erase state/runtime distinctions | Exact asset/task/projection/runtime identity plus scoped private features/lifetimes and batching qualification | Real runtime memory, precision and concurrency tests |
| Repeated traces could self-promote a live classifier | Immutable candidate → protected evaluation → shadow → independent admission; revocation/fallback at dispatch | Actual admission/signing/isolation enforcement |
| Head latency used as system savings | Whole-cascade and amortized cost; account for actual incumbent calls, eligible coverage and verified utility | Measured controlled pilot |
| Optional research could become a hidden release prerequisite | Dedicated bounded contract/shadow/pack profiles, optional later context/richer-learner tasks outside their closure | Live dependency reconciliation |

## Evidence boundary

New Python references actively normalize/decode synthetic records, check exact source/qualification identities and statistical policies, and run mutation tests. They do not execute tools, invoke/train models, fit a real calibrator, fetch schemas/weights, enforce an OS sandbox, publish an artifact or run installed /build-loop. Product gates remain NOT_RUN and tasks retain the pack's proposed statuses; import does not overwrite stronger live evidence in the user's repositories.
