# Axon / MiCode: Jimothy + WebMCP integration review

## Decision

Recommend a coordinated Axon v0.20 / MiCode Axon Support v0.14 design-and-build-plan amendment. These version numbers are recommendations, not generated releases. The supplied v0.19 / v0.13 archives remain unchanged.

Integrate the supported mechanisms into existing owners rather than introducing another Reflex runtime, registry, admission authority, or file format. The current packs already specify most of the broad architecture. The material new work is a schema-ingestion frontend, explicit fixed-task lightweight-distillation experiments, and executable cross-boundary conformance/acceptance cases.

## Scope and observed baseline

Both current package validators exited 0. Axon ran 144 offline tests successfully; MiCode ran 284 offline tests successfully. These are document, schema, inert/reference-fixture and package checks. They do not establish live provider interoperability, trained-model quality, calibration validity, actual sandbox enforcement or product acceptance. No product gate was executed by this review.

MiCode's pinned Axon archive digest matches the supplied Axon archive. No uncoordinated contract migration is needed before the proposed amendment.

## Corrections to the preceding research interpretation

1. A Neural Program is a learned-function artifact, not inherently deterministic code. A Reflex classifier may be packaged as a `.np` under CX-36. No new `.reflex` format or competing registry is warranted.
2. Schema compilation creates a typed decision/composition plan. It does not by itself train weights or qualify a CX-36 Neural Program artifact for deployment.
3. Jimothy's documented bundle trains one fixed question with fixed instructions, criteria and question type; task changes require retraining. A fixed head is not interchangeable with a dynamic-option model for newly discovered tools or changing span catalogs.
4. A bounded action ID can avoid generated tool-name text, but it does not eliminate argument resolution, authorization, dispatch, tool execution or verification. No general single-token/one-pass or no-compaction guarantee follows.
5. Typed output, successful schema compilation, high confidence, teacher agreement, runtime success and independently verified task completion remain separate claims.
6. Human labels retain provenance and adjudication requirements. Approval is not necessarily a factual label; teacher agreement is not task-success evidence.

## Required new or strengthened falsification cases

- Missing active Boolean, member or optional-presence output must not become false, absent or confident success.
- Unsupported schema constructs, unsafe keys/references, oversized recursive schemas, untrusted effect hints and stale schema identities cannot silently produce an executable approximation.
- Dynamic candidate changes cannot reuse a fixed-label head outside its applicability envelope. Reordering must preserve explicit identity mapping or refuse; changed semantics require requalification.
- Missing correct spans/entities must yield explicit absence or observation/fallback. Source offsets, Unicode handling, source version and final types must validate.
- Individually plausible arguments can still form an invalid tool invocation. Evaluate the complete selected action packet and dependent-field constraints.
- Related examples or teacher caches cannot leak protected test labels into training, calibration or threshold selection. Repeated model submissions retain evaluator budgets.
- Model, precision, encoder, preprocessing or execution-profile drift invalidates unsupported calibration reuse; no recommendation cannot imply automatic acceptance.
- Crashed/canceled labeling and effectful work must reconcile durable identity without duplicate publication or duplicate side effects.
- The optimized system must preserve local permission and independent verification, and improve a preregistered end-to-end objective at a useful eligible coverage.

## Suggested implementation sequence

First add owner/consumer contracts, typed schema fixtures and negative cases. Then run one low-risk fixed-domain shadow pilot comparing deterministic rules, TF-IDF and frozen-encoder heads with the incumbent on grouped development and held-out data. Finally qualify deployment and end-to-end outcomes; keep alternative encoders, richer heads, broad schema coverage and learned context reduction as optional experiments unless evidence justifies promotion.

After reviewed source changes, regenerate task/gate manifests and generated views, sync MiCode's pinned owner snapshots and contract lock from the finalized Axon package, update source/review/changelog metadata, and reseal integrity inventories. Keep unchanged wire/artifact versions unless a separately reviewed semantic change genuinely requires a version migration. Product statuses remain NOT_RUN until their actual gates execute.
