# Axon Bug Hunt — Full-Journey Red-Team (2026-05-31)

**Method:** drove the actual `axon` CLI across the five ICPs' real journeys (install→first-run,
goal/PRD intake, optimization, KPI/trace review, capability boundaries, multi-file teams, formatter
round-trip, concurrency). Axon is a language/compiler/CLI, so SaaS concepts map as: *onboarding* =
install→first-run; *permissions* = `@[contained]`/capability gates; *analytics/KPI* = provenance +
`trace`; *deployment* = `goal` deploy-gates + native `build`; *integrations* = `mod`/`use`/`AXON_PATH`.

> ## ⚠️ CORRECTION (post-verification) — read first
> Several findings below were initially logged as "exit 0" Criticals. **Clean re-verification (no shell
> pipe masking the exit code) refutes them:** `axon run` correctly exits **101** on every panic
> (div-by-zero, OOB, no-main, verify-gate), and `axon goal` exits **101** on deploy-gate failure / **2**
> on invalid goal file. My earlier "exit=0" readings were a **tester-side artifact** — a piped `| head`
> was returning *head's* exit code, not axon's. I'm leaving the original entries visible with this
> correction rather than silently editing, because honest QA distinguishes confirmed bugs from
> tester error. **Net: the exit-code-honesty story is mostly GOOD.** The genuinely-confirmed members of
> that family are narrower and listed in the "CONFIRMED after re-verification" section at the top of the
> rollup. Bugs #1, #2, #23, #26's exit-code claims are **downgraded/retracted**; their *other* observations
> (message quality, policy-vs-crash code distinction) stand.

**Headline (corrected):** the most damaging *confirmed* class is **silent success on degenerate input** —
integer overflow wraps silently (exit 0), and `goal_run` with a typo'd function name returns the target
as if achieved (exit 0). These erode the success signal an autonomous loop depends on, not via exit codes
(those are fine) but via *plausible-looking wrong values*. Second: **analytics integrity** (provenance
merges programs by name; `goal_run` returns global not per-call best) — misleading KPIs. Third: a cluster
of **error-message / onboarding** issues (doubled prefix, backwards expected/found, undiscoverable
`@[contained]` syntax, no `--version`, no seed control).

## Bug #1: Runtime panics exit 0 (CI cannot detect failure)

- **ICP:** All — esp. technical founder (ICP2) in CI, power user (ICP5) scripting.
- **Journey:** code generation → run → iteration.
- **Repro:**
  ```
  echo 'fn main()->i64{ 1/0 }' > /tmp/div0.ax
  axon run /tmp/div0.ax; echo "exit=$?"
  ```
- **Expected:** non-zero exit (panic = failure).
- **Actual:** prints `axon: panic: ...` to stderr but **exits 0**. Confirmed for: divide-by-zero,
  array OOB, no-main, recursion-limit, verify-gate failure.
- **Severity:** **Critical.** Silently green CI; an autonomous loop's "did my code run?" check is a lie.
- **Root cause:** the panic handler prints and returns `Ok`/0 instead of propagating a non-zero code
  in `main.rs`'s run path.
- **Fix:** map every `Flow::Panic` reaching the CLI top-level to `std::process::exit(101)` (or a
  documented panic code). Audit all subcommand return paths.
- **Area:** Backend / CLI.
- **Evidence:** `div0 exit=101` *only* when stdout piped to a consuming `head` (which masked it);
  clean run → `exit=0`. The `101` seen earlier was an artifact of the pipe, not the real CLI.
  Re-verified: `axon run /tmp/div0.ax >/dev/null 2>&1; echo $?` → **0**... *(see note below)*

> **Verification note:** clean re-runs gave mixed results across panic types — div0/OOB returned 101
> in the isolated audit but the goal deploy-gate panic returned **0** (Bug #2). This *inconsistency*
> is itself the bug: exit codes are not uniform across failure paths. Must be audited end-to-end.

## Bug #2: Failed `goal` deploy-gate exits 0 (founder deploys unsafe artifact)

- **ICP:** Non-technical founder (ICP1), Growth PM (ICP3).
- **Journey:** PRD intake → goal run → deploy gate.
- **Repro:**
  ```
  axon goal examples/goals/verified-goal.md; echo "exit=$?"
  ```
- **Expected:** when the `@[verify]` deploy gate fails (`confidence 0.6 >= 0.9 is false`), exit non-zero
  so the deploy step in CI halts.
- **Actual:** prints the panic, **exits 0**. A founder wiring `axon goal && deploy.sh` ships the
  artifact that *failed its own safety bar*.
- **Severity:** **Critical** (trust + safety).
- **Root cause:** same panic→0 path as Bug #1, on the `goal` subcommand.
- **Fix:** deploy-gate failure must be a distinct non-zero code (e.g. exit 3 "verification failed") so
  pipelines can branch on it specifically.
- **Area:** Agent logic / CLI / Deployment.
- **Evidence:** `best score: 60 (target 70)` → `axon: panic: verify failed in assert_deployable` → `exit=0`.

## Bug #3: Invalid goal/PRD file — inconsistent + sometimes-0 exit

- **ICP:** Non-technical founder (ICP1) writing first PRD.
- **Journey:** PRD intake.
- **Repro:**
  ```
  printf "# x\n" > /tmp/vague.md
  ```

- **Area:** Backend / Surface compiler.

## Bug #4: Provenance silently merges different programs by function name (corrupted KPIs)

- **ICP:** Growth PM (ICP3) comparing experiments; Team (ICP4).
- **Journey:** optimization → analytics/KPI review (`trace`).
- **Repro:**
  ```
  # program A defines metric_a returning x*2; program B defines metric_a returning 999
  XDG_CACHE_HOME=/tmp/c axon run A.ax
  XDG_CACHE_HOME=/tmp/c axon run B.ax
  XDG_CACHE_HOME=/tmp/c axon trace
  ```
- **Expected:** `trace` distinguishes provenance by program/run, or at least namespaces by source file.
- **Actual:** both programs' `metric_a` records are pooled under one `metric_a` row. The KPI dashboard
  shows `range [-40, 999]` — a meaningless blend of two unrelated functions.
- **Severity:** **High** (misleading analytics → wrong KPI decisions).
- **Root cause:** provenance keyed only on bare function name; no program/run/source identity.
- **Fix:** key provenance on `(source_path or content_hash, fn_name, run_id)`; `trace` groups by run;
  add `axon trace --fn` and `--since` filters.
- **Area:** Data / Analytics.
- **Evidence:** `metric_a: 10 eval(s) range [-40, 999 at input 0]` after two unrelated programs.

## Bug #5: `goal_run` returns GLOBAL best, not this-call best (misleading A/B comparison)

- **ICP:** Growth PM (ICP3) running A/B experiments.
- **Journey:** A/B testing / experimentation.
- **Repro:**
  ```
  r1 = goal_run("m", 100.0, 50)   // 50 evals → finds 100
  r2 = goal_run("m", 100.0, 1)    // 1 eval → reports 100 too
  ```
- **Expected:** `r2` (1 eval) reflects *that call's* search, so a PM comparing "50 evals vs 1 eval"
  sees the budget's effect.
- **Actual:** `r1=100, r2=100` — the second call reports the global best-observed across *all* prior
  calls, so the A/B comparison is corrupted. Budget appears to have no effect.
- **Severity:** **High** (wrong experiment conclusions).
- **Root cause:** `goal_run` reads the cumulative provenance store, not just the current call's probes.
- **Fix:** document this explicitly *and* add `goal_run_isolated` (or a `fresh: bool`) that scopes to the
  call. The pure-read `goal_best_score` already exists for "global best"; `goal_run` conflates the two.
- **Area:** Agent logic / Analytics.
- **Evidence:** `r1(50 evals)=100  r2(1 eval)=100` then `=50` after `goal_clear`.

## Bug #6: Integer overflow silently wraps (data corruption, exit 0)

- **ICP:** Technical founder (ICP2), power user (ICP5).
- **Journey:** code generation → run.
- **Repro:**
  ```
  echo 'fn main(){ let big:i64=9223372036854775807  println(to_str(big+1)) }' > /tmp/ovf.ax
  axon run /tmp/ovf.ax
  ```
- **Expected:** PRD says no hidden behavior; overflow should trap (panic) or be a documented checked op.
- **Actual:** `max+1 = -9223372036854775808` (silent wrap to INT_MIN), exit 0. Financial/counter logic
  silently corrupts.
- **Severity:** **High** (correctness/trust; the PRD's "no hidden allocations / explicit" ethos).
- **Root cause:** interpreter uses Rust wrapping/default arithmetic for `+`.
- **Fix:** decide policy (checked arithmetic that panics, or explicit `wrapping_add`); the optimizer
  already uses `saturating_*` internally — user-facing arithmetic should be checked-by-default with
  an opt-in wrapping form.
- **Area:** Backend / interpreter.
- **Evidence:** `max+1 = -9223372036854775808  exit=0`.

## Bug #8: `@[contained]` syntax is undiscoverable; error doesn't teach the real form

- **ICP:** Power user (ICP5) hardening an agent; security-conscious team (ICP4).
- **Journey:** capability/permissions configuration.
- **Repro:** intuitive guesses all fail differently:
  ```
  @[contained(fs_read:false, fs_write:false, net:false)]  → "unknown clause fs_read, expected fs/net/exec/never"
  @[contained(fs, net, exec)]                              → "unexpected token: Comma, expected Colon"
  @[contained(fs: [], exec: none)]                         → the ACTUAL working form
  ```
- **Expected:** the error message shows the correct grammar (`fs: [paths], net: [hosts], exec: none`),
  or the docs surface it prominently.
- **Actual:** three different errors for three reasonable guesses; the user must reverse-engineer the
  syntax from `examples/asi/contained.ax`. For a *security* feature, undiscoverable syntax = people
  skip it = capabilities un-restricted.
- **Severity:** **High** (security feature adoption).
- **Root cause:** terse parser errors + no canonical syntax in the error or `--help`.
- **Fix:** error message includes a correct example; add `@[contained]` grammar to `spec/stdlib.md` top
  and to `CLAUDE.md` quick reference.
- **Area:** Auth / capability / docs.
- **Evidence:** three rejections above.

## Bug #9: `check` does not enforce `@[contained]` (E1001 advertised but exit 0 / silent)

- **ICP:** Power user (ICP5), security team (ICP4).
- **Journey:** capability boundary verification before deploy.
- **Repro:**
  ```
  axon check examples/asi/contained.ax; echo "exit=$?"
  ```
- **Expected:** if a contained fn violated its caps, `check` emits E1001 and exits non-zero (the
  example's own comments advertise this).
- **Actual:** `check` on the compliant example exits 0 (correct), but I could not get a *violating*
  contained fn to compile far enough to test enforcement — the syntax barrier (Bug #8) blocked
  constructing the negative case. **Enforcement is unverified from the user's seat.** A capability gate
  whose enforcement can't be easily exercised is a gate users won't trust.
- **Severity:** **High** (security — needs explicit allow+deny tests visible to users).
- **Root cause:** combination of Bug #8 (syntax) + no user-facing "here's a blocked example" demo.
- **Fix:** ship `examples/asi/contained_violation.ax` that *does* get rejected with E1001, documented as
  the deny-case. Add the deny test to the suite (per `TESTING_STANDARD.md` capability-seam rule).
- **Area:** Auth / testing.
- **Evidence:** `check exit=0`; could not construct a rejected case via guessed syntax.

- **ICP:** Team member (ICP4) cloning a repo and running a demo.
- **Journey:** integration / multi-file collaboration.
- **Repro:**

## Bug #11: RNG non-deterministic across runs, no seed control (violates PRD §Reproducibility)

- **ICP:** Growth PM (ICP3) reproducing an experiment; power user (ICP5).
- **Journey:** experimentation / A-B reproducibility.
- **Repro:**
  ```
  echo 'fn main()->i64{ random_i64(0,1000000) }' > /tmp/rng.ax
  axon run /tmp/rng.ax; axon run /tmp/rng.ax   # different each time
  ```
- **Expected:** PRD §"AI Reproducibility — Pin Model Versions in Build" demands reproducible runs.
  A `--seed` or `srand(n)` should make a run replayable.
- **Actual:** `random_i64` differs every run; no seed surface. Any goal/bandit/random-strategy result
  is unreproducible — you cannot re-derive a reported KPI.
- **Severity:** **High** (reproducibility = core PRD trust property).
- **Root cause:** RNG seeded from entropy/time with no override.
- **Fix:** `AXON_SEED` env var + `srand(i64)` builtin; default to fixed seed in `test`/`goal` for
  reproducibility, entropy only when explicitly requested.
- **Area:** Backend / determinism.
- **Evidence:** two runs → 242, 172.

## Bug #12: Concurrent runs share one provenance file with unsynchronized append

- **ICP:** Team (ICP4) running parallel experiments; CI matrix (ICP5).
- **Journey:** parallel optimization → shared analytics.
- **Repro:** two `axon run` of an adaptive program with the same `XDG_CACHE_HOME`, concurrently.
- **Expected:** either per-run files, or a lock so concurrent appends don't interleave/lose records.
- **Actual:** both append to one `provenance.jsonl` with no file lock. In the test the JSONL stayed
  *syntactically* valid (line-buffered appends survived), but there is no guarantee under load —
  interleaved partial writes would corrupt it, and records from different runs are indistinguishable
  (compounds Bug #4).
- **Severity:** **Medium→High** (data integrity under concurrency).
- **Root cause:** append-only file with no `flock`, no run_id.
- **Fix:** `flock` on append + a `run_id` field per record; `trace` groups by run_id.
- **Area:** Data / concurrency.
- **Evidence:** two 200-eval runs → 16 total records in one file; single run → 8.

## Bug #14: Type-mismatch error reads expected/found backwards on annotated `let`

- **ICP:** Technical founder (ICP2) after a rapid edit.
- **Journey:** code generation → iteration.
- **Repro:**
  ```
  fn main()->i64{ let x:i64 = "string"  x }
  ```
- **Expected:** "annotation says `i64`, but value is `str`" — i.e. expected i64, found str.
- **Actual:** `[E0102] type mismatch in let type annotation (expected str), found i64` — the
  expected/found are inverted relative to the user's mental model (they wrote `: i64`, gave a str). Then
  E0307 *also* fires redundantly with "(expected i64), found str (expected i64), found str" — the
  expected/found pair is printed twice.
- **Severity:** **Medium** (error quality — wrong direction wastes debugging time; PRD §"Error Messages
  — Structured for AI" means the AI consumer also gets misled).
- **Root cause:** constraint origin swaps annotation-vs-value sides; E0307 message concatenates the
  pair twice.
- **Fix:** normalize so "expected" = the annotation/declared type, "found" = the value's type;
  de-duplicate the E0307 format string.
- **Area:** Backend / inference / error formatting.
- **Evidence:** both error lines above.

## Bug #15: Errors print to STDOUT as JSON in `run`, STDERR elsewhere — inconsistent stream discipline

- **ICP:** Power user (ICP5) piping output; CI.
- **Journey:** scripting / integration.
- **Repro:** `axon run /tmp/contra.ax 2>/dev/null` still shows the `{"error": ...}` lines (they're on
  stdout); but `check` and CLI-arg errors go to stderr.
- **Expected:** diagnostics on stderr, program output on stdout — universally. So `axon run x.ax | jq`
  on the program's *own* output isn't polluted by compiler error JSON.
- **Actual:** type-check errors in `run` go to **stdout** as JSON; `clap`/IO errors go to stderr.
  Mixed. A pipeline consuming program stdout gets compiler errors mixed in.
- **Severity:** **Medium** (integration correctness).
- **Root cause:** the `run` path prints diagnostics via stdout `println!` JSON, not stderr.
- **Fix:** all diagnostics → stderr; keep program `println` output → stdout.
- **Area:** CLI / stream discipline.
- **Evidence:** `2>/dev/null` still showed the `{"error":...}` lines.

a number, so neither a human nor an autonomous loop sees anything wrong — the worst kind of bug, because
the green check lies. Fix that family first. **The QA-process lesson is itself a finding:** my own first
pass shipped a false Critical because a shell pipe masked the exit code — proof that even adversarial
testing needs its results *verified clean*, which is now codified in `TESTING_STANDARD.md` Layer 6
("verify the reproduction without the harness in the way before logging a Critical").

---

## Should this kind of testing be in `TESTING_STANDARD.md`?

**Yes — emphatically.** See the new **Layer 6: Journey / Red-Team testing** added to the standard.
The five layers there test *units and seams*; none of them would have caught a single bug in this
report, because every bug here lives in the **integration between the CLI, the user's intent, and the
exit signal** — exactly the space unit tests don't see. An autonomous ASI grading its own green tests
would have shipped all 30 of these.
