# Observer service: what the operator kit and runbook must add (amendment 68, G1 = A)

This note lists the changes for a later merge into the kit
(`scripts/operator_deploy_protected_host.sh`, `scripts/test_operator_deploy.sh`) and into
`governance/notes/v022-operator-runbook.md`. This branch (`c9r4b/observer`) does not edit those
files, because another branch is changing them now.

## What changed in the code the kit deploys

- New binary `axon-observer` (a bin of `axon-fabric`). It runs as its own uid, is started by
  systemd socket activation, reads only `/etc/axon/observer.json`, and serves only uid 0.
- `axon-protected-launcher --observe` is a new helper operation. Fabric uses it to get the
  observation. The helper reaches the observer itself and checks the observer PROGRAM against a
  pin in the helper config.
- A **production** Fabric now REFUSES a host config whose `observer` section names a `command`.
  Before this change, the kit installed the operator's observer program and pinned it as
  `observer.command`. That route no longer exists in production.

## 1. The uid

- Create the system user and group `axon-observer`: own uid, no login shell, no home directory.
- Do not add it to the `axon-fabric` group. Do not add the Fabric user, or any agent user, to
  its group.
- Choose a uid that is not the Fabric's, the custodian's or root's. The configs below must name
  it.

## 2. The binary

- Install the production build at `/usr/local/libexec/axon/axon-observer`, owned `root:root`,
  mode `0755`. Pin it like the custodian: record its sha256 from the INSTALLED bytes.
- The kit's `--observer-bin` / `--observer-interpreter` (the in-uid observer program) is no
  longer installed or pinned in `/etc/axon/protected-host.json`. Remove those options, or turn
  them into a refusal that says why (amendment 68).

## 3. The key (path, owner, mode, custody)

- Path: `/var/lib/axon-observer/key/observer.pk8`.
- Owner `axon-observer:axon-observer`, mode **0400**. The directory
  `/var/lib/axon-observer/key` is `axon-observer`, mode **0700**. `/var/lib/axon-observer` is
  root-owned 0755; systemd's `StateDirectory=` creates it that way.
- The key is generated BY THE OPERATOR, AS that user, on the host:
  `sudo -u axon-observer /usr/local/libexec/axon/axon-fabric keygen --out /var/lib/axon-observer/key/observer.pk8`.
  `keygen` writes 0400 and prints `public_key`. The kit never generates or holds this key, as
  with every other operator key.
- Public half: `/etc/axon/trust/observer/observer.pub`, `root:root` 0644, containing the 64-hex
  `public_key`. It replaces the observer key the runbook's step 5 table currently describes as
  "the observer's own custody". It must be in NO other `/etc/axon/trust/*` root (ADR-002; the
  service refuses to start otherwise).
- Refused by the service at start (exit 2, nothing served):
  - a key that is group/other-readable or owner-writable (any ACL grant shows in the group
    bits);
  - a key owned by any uid other than `axon-observer` (the Fabric's included);
  - a symlink;
  - a key whose public half is not in `/etc/axon/trust/observer`.

## 4. The record store

- Path: `/var/lib/axon-observer/observed`, owned `axon-observer`, mode 0700. The unit's
  `StateDirectory=axon-observer/observed` creates it. Its parent chain is root-owned and not
  writable by group or other.

## 5. Config file: `/etc/axon/observer.json` (`axon-observer/1`)

`root:root` 0644. Example: `profiles/protected-host/observer.json.example`.

```json
{"schema": "axon-observer/1", "observer_uid": <axon-observer uid>, "fabric_uid": <axon-fabric uid>,
 "caller_uid": 0, "socket": "/run/axon-observer/observer.sock",
 "store": "/var/lib/axon-observer/observed", "key_path": "/var/lib/axon-observer/key/observer.pk8"}
```

Rules the service enforces in protected mode:
- `observer_uid` is neither `fabric_uid` nor 0;
- `fabric_uid` is not 0;
- `caller_uid` is 0;
- there is no `test_paths` key.

## 6. Config field changes in the existing configs

- `/etc/axon/protected-launcher.json` (`axon-protected-launcher/2`, still `/2`): add
  `observer.service = {"socket": "/run/axon-observer/observer.sock", "uid": <axon-observer uid>,
  "sha256": <sha256 of the INSTALLED axon-observer>}`. A production helper refuses a `uid` equal
  to `fabric_uid` or 0, and refuses a pin that is not a lowercase sha256. Without
  `observer.service` the helper relays no observation, so no protected launch can be observed.
- `/etc/axon/protected-host.json`: the `observer` section keeps `custodian` (and `max_age_s` if
  set). It must NOT contain `command` or `interpreter`; a production Fabric refuses `command`.
  `gen_configs` must stop emitting them.
- `scripts/trust_root_preflight.sh` reads `axon-fabric protected-host-paths`, which now lists
  `observer.command` only when present. No change is needed for it to keep working.

## 7. systemd units

Install `profiles/protected-host/systemd/axon-observer.socket` and `axon-observer.service` under
`/etc/systemd/system/`, owned `root:root` 0644, and enable the socket.

The socket is `ListenStream=/run/axon-observer/observer.sock`, `SocketUser=root`,
`SocketGroup=root`, `SocketMode=0600`, `DirectoryMode=0755`. Only root can connect; the helper
connects as root. That `ListenStream` path must equal:
- `socket` in `/etc/axon/observer.json`;
- `observer.service.socket` in `/etc/axon/protected-launcher.json`.

## 8. Preflight checks to add (`trust_root_preflight.sh`, protected mode)

- **Actor.** Take `--observer <uid>`. It must be `observer.json`'s `observer_uid`. It must differ
  from the Fabric, the custodian, the verifier and every agent, and must not be root.
- **Key read.** The Fabric uid and every agent uid FAIL to `open(O_RDONLY)` the key, tested by a
  real attempt per actor. The observer uid succeeds.
- **Key write.** Nobody but root can create or chmod a file in the key directory or the store.
- **Socket connect.** The Fabric uid and every agent FAIL to `connect` to
  `/run/axon-observer/observer.sock`. The observer also refuses them by `SO_PEERCRED`, but the
  socket mode is the first barrier.
- **Unit pin.** The running unit's `MainPID` executable hashes to `observer.service.sha256`. The
  helper checks this on every reply; the preflight reports it at deploy time.
- **Config and trust root.** `/etc/axon/observer.json` and `/etc/axon/trust/observer` are
  operator files (the existing operator-file probes).

## 9. Runbook edits

- **Step 0:** replace the "observer program and its key custody … recorded follow-up" bullet
  with: the observer is the `axon-observer` service (amendment 68). State what it measures and
  what it is told (amendment 68's table). The operator's remaining decisions are:
  - the observer uid;
  - key generation and custody (generated as that uid on the host, never copied off);
  - unit installation.
- **Step 3 (install):** add the `axon-observer` user, binary, config, units and key directory.
  Drop `--observer-bin`.
- **Step 5 (keys table):** the observer key row becomes:
  - private: `/var/lib/axon-observer/key/observer.pk8`, `axon-observer` 0400, dir 0700,
    generated by the operator as `axon-observer`;
  - public: `/etc/axon/trust/observer/observer.pub`, root 0644.
- **Known gaps list:** remove item 3 ("The observer runs as the Fabric uid"). Add: the observer
  measures INSTALLED files and the running Fabric. The guest policy, nonce, epoch, the init and
  axon digests inside the measured rootfs, and the Fabric revision are TOLD (amendment 68).
- **Kit test (`test_operator_deploy.sh`):**
  - the dry run shows the observer user, binary, config, units and key directory with their
    owners and modes;
  - a host config with `observer.command` is never generated;
  - the helper config carries `observer.service` pinned to the installed `axon-observer`.
