## 6. Findings

### S0Merge-1 — BLOCKER — S0 lands seal code before S1, so sealed runs execute on the VM with no seal
- **Spec:** §11 "S0 merge everything outside the interpreter …"; "S1 … landed on main BEFORE any seal code"; and the
  Rollback line "before S7, main keeps working with the seal absent (the pin refuses sealed runs it cannot protect)".
- **Evidence:**
  - S0 brings `--seal`, the resolver sealed set, the sealed-only check, the axon-psv/fabric/cortex runners and the
    custodian. These are seal code, so the DAG `S0 → S1` contradicts S1's own premise.
  - The executed probe (`/tmp/r51/s0-probe`, scratch binary) ran the env-cleared `axon test --seal`, which prints VM
    trace lines and `"status":"ok"`.
  - 41 sealed attack tests fail on the S0 tree (table above). Each failure is an attack that is no longer refused.
  - The Fork 1 pin as specified refuses only `AXON_ENGINE=vm`. With the variable unset it runs on the tree. On
    S1–S4 the tree has no runtime seal (taint arrives in S2–S3, PICK in S4, pins in S5), so S1 does not make
    `--seal` safe either. The Rollback sentence is false for S1–S4.
- **Proposed edit:**
  - Re-order to `R50 → S1 → S0 → S2 …`.
  - Re-define S1 as: "every sealed entry (`--seal` with a non-empty sealed set, which covers the axon-psv,
    cortex and fabric runners, and the sealed check child) **refuses** with the §6 exit code and a stated message,
    whatever the engine. The refusal is lifted only in the slice that completes PSV-1 on the tree (after S5), and at
    that point it becomes the Fork 1 tree pin (VM refused)."
  - The pin must key on the sealed set, not on `AXON_ENGINE`: runners call `env_clear()`, so the variable is never
    set in a sealed child (runner.rs:327; cortex runner.rs:2270).
  - T1 must exercise the env-cleared runner invocation, not only the direct CLI with `AXON_ENGINE=vm`.

### S0Merge-2 — MAJOR — the S0 test plan cannot be "builds and passes its tests"
- **Spec:** §11 "Slices, each a commit that builds and passes its tests".
- **Evidence:** §3 table. 41 runtime-seal tests, `dispatch_rule_switch_is_test_only` (reads `interp/pin.rs`),
  `refusal_coverage_gate` (0/53, the `.py` opens `interp/conform.rs`) and `pci_delta_note` (0/6, the note is pinned
  to a git head) all fail on any S0 tree. `gate.sh --strict` cannot be green at S0.
- **Proposed edit:** S0 gets an explicit **deferred-test registry** (file + test name → the slice that re-enables
  it). Each deferred test is marked `#[ignore = "R51 Sn: <reason>"]`, and a drift test fails if the ignore set differs
  from the registry. Do not split or move these files: moving them changes the evidence anchors Fork 4 relies on.
  Under S0Merge-1's ordering, the sealed suites become refusal-expecting until S5. State that S0 is accepted on the
  non-deferred set plus `cargo check --workspace --all-targets` and fmt/clippy, and that `gate.sh --strict` is first
  required at S6.
