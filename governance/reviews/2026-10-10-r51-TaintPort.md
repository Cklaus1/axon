## 0. Summary of findings

| ID | Sev | Spec claim | One line |
|---|---|---|---|
| TaintPort-1 | BLOCKER | Fork 3 bullet 1 "every value that crosses a seal edge is deep-copied" | Neither needed nor safe. Struct/Enum/Tuple/Array/Str are copy-on-write on main, so no alias can be written. Dict/Chan/closure cells use reference semantics: copying them changes what honest programs do, and veto does not copy them (it snapshots and checks). `Rc::make_mut` is shallow, so it would not even reach a nested dict. |
| TaintPort-2 | BLOCKER | Fork 3 bullet 2 "address-keyed taint tables extend to … `StructVal` fields via `&mut` write-through" | Cannot work. A COW write moves the value to a new address, so the taint is lost on the first write (std `Rc::make_mut` does this under strong *and* weak sharing). It is also unnecessary: veto carries the taint of value-semantic containers on the binding. |
| TaintPort-3 | BLOCKER | Fork 2 "`define_var`/`assign_var` gain taint-aware twins used by the seal code" | Veto made the taint a REQUIRED argument of every `define` (veto interp.rs:552-555) so that no site could drop it. Twins "used by the seal code" bring that hole back: ordinary let/match/for/param binding sites in operator frames must record taint. A parallel vector that is not updated at a site gets out of step, and a binding then reads another binding's taint (under-taint). |
| TaintPort-4 | BLOCKER | Fork 2 "`Option<Vec<u8>>`… allocated only in a sealed run" | `Env::new()` has no access to `Interp`. 7 tree sites build fresh `Env::new()` predicate envs, plus `Env::from_snapshot` for handler arms and continuations. In a sealed run these would carry `None`, and if `None` reads as 0 the taint is silently dropped. Needs a fail-closed rule. |
| TaintPort-5 | MAJOR | Fork 3 (closures) | Main asserts `size_of::<Value>() == 16` (main interp.rs:129), so veto's per-REFERENCE closure `contract` (veto interp.rs:104-112) cannot go inline. If the port puts it in a new `Rc<ClosureVal>` per cast, then (a) the capture cell cannot be shared (`captured: RefCell<…>` is inside `ClosureVal`), and (b) `taint.picked`, which is keyed by capture-cell address, misses the re-wrapped closure. That is a PICK bypass. The spec has to choose a representation. |
| TaintPort-6 | MAJOR | §11 DAG "S2 -> S3 -> {S4, S5}" | Inverted. `taint.rs` (S2) calls `pin::` and `self.pins` (8 sites) and `self.seal`/`frame_sealed` (18 sites), so S2 cannot compile before S5's `pin.rs` and S3's `Seal` state. S5 is the data-model-independent slice and should land first. |
| TaintPort-7 | MAJOR | §11 slice list | It omits veto machinery that has no main counterpart: the per-frame `Kernel` split (96 `self.<kernel field>` refs on main), `contain_frame`/`contain_loop_control`, `TestEnd`/`run_test_fn_outcome` (the runner's verdict surface), `no_such_fn` (the existence-oracle text behind T4), `with_frame`/`handler_may_answer`, the sealed RNG stream, and `kernel.rs` `new_sealed`. |
| TaintPort-8 | MAJOR | Fork 2 (main-only read paths) | The main-only in-place fast paths `operand` (AX-55), `index_in_place`, `field_in_place`, `assign_in_place_shaped`, `write_place`, `call_mut_with`, `chan_method`, `dispatch_call`/`dispatch_named`/`impl_method` have no counterpart on veto. Each is a new taint and edge sink that a port of veto hunks will not touch. |
| TaintPort-9 | MAJOR | S6/T7 drift tests | Veto's source-scanning drift tests use names that do not exist on main: `fns.get(`, `globals`, and `interp_sources()` without `vm/*.rs` and `sym.rs`. Main resolves callees through `fn_of_sym` (main eval.rs:1229, 1295, 1874), which the detector does not see, so the tests can pass without checking anything. Their `cut()` marker would also truncate `vm/mod.rs` at line 30. |
| TaintPort-10 | MAJOR | Fork 2 "taint is touched only on the tree path, which unsealed runs mostly do not take" | False. Under the default VM, S9 runs every fn's first entry on the tree (`first_entry_on_tree`, main vm/mod.rs:1317), and `Op::Tree` calls `self.eval` (vm/mod.rs:2012). Taint branches in `eval`/Env methods are therefore on the path `vm_perf_gate` measures. |
| TaintPort-11 | MAJOR | Fork 2 "indexed by the same slot … the name-check scan fallback keeps both vectors in step" | `get_var`/`get`/`get_mut` return `&Value`, not an index. Veto read taint *by name, innermost* (`taint_of`, veto interp.rs:573), while main reads values *by slot*. A port has to read value and taint from one index, or the two can come from different bindings. |
| TaintPort-12 | MAJOR | T8 "candidate keeps an alias to an operator struct … mutates it" | Under COW this cannot happen, so T8 as written passes without testing anything. The real new attack classes are listed in §4.3. |
| TaintPort-13 | MINOR | S5 "nearly verbatim" | True for `pin.rs`, `seal_split.rs`, resolver, parser (`eof_span`, `parse_type_text`), checker, kernel.rs: 0 textual conflicts. ### 3.2 Does a parallel `Option<Vec<u8>>` stay in step?

Only if every site above is converted. Nothing in the spec's design enforces that, so the risk is concrete:
- **Slot resolution and the name-scan fallback:** `get_var` returns `&Value`, so the fallback scan needs a twin that returns an index (TaintPort-11). Veto's `t_holder` reads `env.taint_of(name)`, the innermost binding by name. Main reads values by slot. Copying veto's logic gives two different lookups for value and taint.
- **`define_var` padding:** `resize_with(i, (SYM_NONE, Unit))` at 727. The taint vector must be padded in the same way with zeros.
- **Scope push/pop:** `pop` truncates `vars` to the mark, and the taint vector must truncate with it. `clear` has an `unsafe set_len(0)` fast path that must also clear the taint vector.
- **Closure capture:**
  - The AX-40 lend path swaps the cell's `Vec` into `env.vars` (4649) and back (4680). The capture's taints need a home in `ClosureVal` and must swap with it.
  - The copy path extends from the cell (4653) and writes back positionally (4685). The taints need the same zip.
  - `make_closure` (main eval.rs:658) captures `(s, v.clone())` per free variable. The taints have to be captured in parallel.
- **`drain_base_scope`:** does not exist on main. Its job is done by the lend swap and the positional write-back, so the port has to rewrite veto's `drain_base_scope_into`/`load_captured` logic onto those, not transplant it.
- **Frame reuse:** `give_frame` → `clear` → pool. A frame's taint vector must be emptied on every give, and a pooled frame taken during a sealed run must come back `Some`. The allocation-free fast paths (`bind_params` raw `extend` 4205, `goal_met` push 3991/4130, slotted param push 4661-4663) write `vars` directly and skip every Env method.
- **`call_mut_with`:** the value is moved out of the caller's binding (`mem::replace` with `Unit`, eval.rs:1331), bound as the callee param, and moved back (1362). Its taint has to travel both ways. Veto's `call_fn_mut` returns the outs' taints (`Vec<u8>`, veto interp.rs:3495).

Conclusion on Fork 2: the parallel vector is workable, but only with the type-level enforcement veto had. **Proposed spec edit (Fork 2 b):**
> Env's binding storage becomes private to a `Bindings` type whose every mutating method takes `t: u8`; there is no taint-free binding method. Unsealed runs pass `0` and the taint store is an empty `Vec<u8>` with an `if sealed` guard, or the evaluator is monomorphised as veto's `eval_t<const T>`. Raw `env.vars` access outside `Bindings` is a compile error (private field). `debug_assert!(taints.is_empty() || taints.len() == vars.len())` runs after every method. In a sealed run the same check runs in release builds, and a mismatch is a panic: fail-closed.

### 4.2 Deep copy and address keys

**Deep copy at edges.**
- For COW types it is not needed: aliasing cannot be observed.
- For Dict, Chan and closures it is *wrong*. It changes what honest programs do in a sealed run, for example:
  - an operator fn that fills a dict passed in by the candidate;
  - a channel shared with a spawned body;
  - a counter closure shared by `let b = bump` (T40).
  
  That breaks §8 T8's own requirement ("honest code that shares its own values is unaffected") and §7 I-2.
- Veto does **not** copy. It snapshots the dicts reachable at an edge and checks the operator-side state on the way back (`dict_edge_in`/`dict_edge_out`/`replaced_ok`, conform.rs:1383-1600), stamps channel contracts (`chan_contracts`, interp.rs:168-174), and gates closures by provenance marks plus `picked`. `grep -nE "deep.?cop|fn (unshare|detach|sealed_copy|fresh_copy|copy_out)"` over veto's interp finds no deep copy.
- The mechanism the spec names, `Rc::make_mut`, clones only the outer Vec or struct. Nested `Rc<RefCell<…>>` dicts stay shared, so it would not even achieve the stated goal.

**Address-keyed tables.**
- Veto's guard against address reuse is sound for Dict and Chan:
  - `taint.objs` and `taint.picked` keep a strong `Value` clone, so the address cannot be freed (veto taint.rs:117-121, 945, 983).
  - `DictSnap` and `ChanEntry` hold a `Weak`. A live `Weak` keeps the `RcBox` allocated, and the lookup re-checks with `Rc::ptr_eq` on `upgrade()` (conform.rs:1628-1641).
- Extending these tables to COW payloads (`StructVal`) fails for two reasons:
  - **Strong key:** the strong clone makes `strong_count ≥ 2`, so the next write copies into a new allocation. The taint stays on the old address and is lost for the written value. It also turns every AX-31 in-place write into an O(n) copy.
  - **Weak key:** `Rc::make_mut` with no other strong reference but live `Weak`s *disassociates the Weaks and moves the value into a new allocation* (std docs, `Rc::make_mut`: https://doc.rust-lang.org/std/rc/struct.Rc.html#method.make_mut). The address changes again. `Rc::get_mut` also returns `None` while a Weak exists, so main's in-place fast paths (vm/mod.rs:1204/3157) quietly turn into copies.
- Veto never needed taint by address for value-semantic containers: "Arrays are not scanned: an element is read out by an expression, and that read carries its holder's taint" (veto taint.rs:850-851). The binding taint plus `t_stored` on writes is the model, and it carries over to main unchanged.

**Proposed spec edit (Fork 3), replacing bullets 1-2:**
> Values cross seal edges by Rc share exactly as on v0.22. Value-semantic payloads (`Str`, `Array`, `Struct`, `Enum`, `Tuple`, `Decimal`, `Handle`) are copy-on-write or immutable on main, so no alias can be written. Their taint rides on the binding and on the accumulator (Fork 2), never on an address. The reference-semantic objects are unchanged from v0.22 (Dict, Chan, closure capture cell), and so are their mechanisms: dict snapshots and checks at edges, channel contract stamping, `objs`/`picked` keyed by `Rc::as_ptr` with a strong clone as the reuse guard. Closures are keyed by `Rc::as_ptr(&Rc<ClosureVal>)` (the capture cell's owner). No value is deep-copied at an edge. A drift test asserts that `addr_of` covers exactly Dict, Chan and Closure.

**Closure contract representation (TaintPort-5), decision needed in Fork 3:**
- `Value` is pinned at 16 bytes (main interp.rs:129), so `Closure(Rc<ClosureVal>, Option<Rc<Contract>>)` is out.
- Option A: `ClosureVal { code, captured: Rc<RefCell<Vec<…>>>, contract: Option<Rc<Contract>>, seal: SealMarks }`. A cast allocates a new `ClosureVal` that shares `captured`. `picked` and every identity test then key on `Rc::as_ptr(&captured)`, not on the `ClosureVal`. AX-40's `strong_count(cv) == private_refs` must become `strong_count(captured) == private_refs`.
- Option B: keep contracts in a side table keyed by the `ClosureVal` address. That changes veto's per-reference semantics ("one closure used at two types is not confused", veto interp.rs:108-111) and needs a new argument.

Either way, add a T8 case: *a candidate PICKs an operator closure from a table and passes it through a `fn(..)`-typed parameter (re-wrap), then the operator calls it; it must be refused.*

### 4.3 Attack classes T8 is missing (proposed T8 replacement list)

1. **PICK laundering by identity change:** a cast re-wrap, a `SendValue` round-trip (main interp.rs:2423-2436 builds a fresh `ClosureVal`), or a `fn_value` forwarder (main eval.rs:210, fresh per use) gives a picked operator closure a new key.
2. **Taint-vector desync:** for each raw `vars` write in §3.1 (`bind_params` 4205, `goal_met` 3991/4130, lend swap 4649/4680, `extend_from_slice` 4653, padding 727), a candidate value bound right after must keep its taint. Test with a positional probe: a tainted binding followed by an untainted one, then use the untainted one at a sink.
3. **Fresh `Env::new()` predicate envs** (interp.rs 4095/4492/4557, eval.rs 690/1826/1849): the predicate runs on a candidate value inside an operator frame and must keep that value's taint (veto passes `entry_t`, interp.rs:4168-4171).
4. **Handler-arm and continuation snapshots** (eval.rs 1391/1403 → 1421/1461/1521/1542): taint must survive `snapshot()`/`from_snapshot`.
5. **AX-55/AX-31 in-place reads and writes:** `operand` (1589), `index_in_place` (1733), `field_in_place` (1747), `assign_in_place(_shaped)` (1623/1712), `write_place` (interp.rs:4814). Use each with a tainted local at a width/dispatch/name sink.
6. **Lend path:** a closure called with `strong_count == private_refs` runs with its capture moved into the frame. Its capture taints must move with it and come back.
7. **Frame pool reuse:** a frame given back after a sealed call and taken by an operator call must not carry stale taints, and must not come back `None` in a sealed run.
8. **Name scan vs slot:** a binding resolved through the `get_var` name fallback must read the taint of the same binding.
