# Tech Spec — R6: Capability & Registry Security

**Status:** ✅ Reviewed (2026-06-01)
**Requirement:** `../REQUIREMENTS.md` R6 — *Capability security: content-addressed imports, compile-time I/O restriction, AI audit on import.*
**Decisive fork (from `README.md`):** *Content-addressing model.* Imports are content-addressed (hash = identity, no names). Decide **the hash scheme, the lockfile format, and *when* the AI-audit-on-import runs** (install-time vs. compile-time). Security boundary — under-spec = exfiltration. Pairs with `ARCHITECTURE_INVARIANTS.md` I-11/I-12. **→ Resolved below.**

---

## 1. Motivation

Imports today are **name-based and integrity-free**. `use a::b::c` searches each dir on `AXON_PATH` (then `~/.axon/lib`, then `<bin>/../lib/axon`) and **the first `a/b/c.ax` that exists wins** (`lib.rs:336` `load_use_decls`, `lib.rs:296` `axon_search_dirs`). Consequences:

- **No integrity:** a module's bytes can change between builds with no signal. Two machines with different `AXON_PATH` contents silently compile *different* programs under the same `use`.
- **Substitution attack:** prepending a dir to `AXON_PATH` (or dropping a file in `~/.axon/lib`) shadows any module — the classic dependency-confusion / left-pad substitution vector.
- **No audit:** an imported module can contain `@[contained(...)]`-free I/O or `never:`-evading code; nothing inspects a dependency's capability surface *before* its code joins the program. The capability checker (`capabilities.rs`, E1001–E1004) runs on the *merged* program, but a malicious import could still widen the trusted surface via name collisions (E0903 only *warns*/drops; it doesn't quarantine).

R6 closes this: **identity = content hash**, pinned in a **lockfile**, with an **AI-audit gate** on first acquisition. This spec's job is to resolve the three forks (hash scheme / lockfile / audit timing) on paper, because each is a security boundary that is cheap now and an exfiltration risk if discovered mid-implementation.

Design-only. No implementation code lands until **Reviewed** (`README.md` / `BUILD_PROTOCOL.md` Gate 1). The interpreter is the reference path (I-2); codegen import-verification parity is deferred (§11). This pairs tightly with **I-11** (capability boundary is real and total) and **I-12** (self-modification cannot weaken the TCB).

## 2. Requirement link

`../REQUIREMENTS.md` **R6** (25%, ⚠️ Partial). Quoted acceptance:

> *Import without declared capability fails compile; tampered content hash rejected.*

Two binary gates this spec must make testable:
1. **Tamper rejection:** an imported module whose bytes don't match the lockfile hash → hard compile error, no execution.
2. **Capability declaration:** an import that performs I/O the importer didn't grant → compile error (extends the existing `@[contained]` boundary across the import edge).

Overlaps: **I-11/I-12** (TCB), **R3** (AI-audit reuses the `ai_call` provenance schema from `R3-ai-primitive.md` §4.3), **R4** (provenance of the audit decision must be un-opt-out-able).

## 3. Surface (what the user writes)

### 3.1 Content-addressed import

```axon
// Names stay for ergonomics, but identity is the hash. The name resolves to a
// hash via the lockfile; the bytes on disk must match that hash or the build
// fails. A bare `use` with no lockfile entry is an error in --locked mode.
use scorelib::metric            // resolved through axon.lock to a specific hash
```

### 3.2 The lockfile (`axon.lock`, the resolved fork)

```toml
# axon.lock — generated by `axon add` / `axon lock`, committed to the repo.
# Format: TOML, one [[module]] per resolved import. Deterministic key order.
version = 1
[[module]]
name   = "scorelib::metric"          # the `use` path
hash   = "axh1:9f2b…"                 # algorithm-tagged content hash (§4.1)
source = "file:./vendor/scorelib/metric.ax"   # where the bytes came from
caps   = ["fs:read(./data/)"]         # the module's DECLARED capability surface (§4.4)
audit  = "axh1-audit:7c…"             # hash of the AI-audit record that cleared it (§4.5)
```

### 3.3 CLI surface

```
axon add scorelib::metric ./vendor/scorelib/metric.ax   # hash, audit, write axon.lock
axon lock                         # re-resolve all imports, rewrite axon.lock
axon check  prog.ax --locked      # NEW: every use MUST match axon.lock or fail (CI mode)
axon check  prog.ax               # dev mode: missing lock entry is W1210, not fatal
axon audit  scorelib::metric      # re-run the AI capability audit, print the report (JSON)
axon verify-lock                  # recompute every hash, compare to axon.lock (tamper check)
```

### 3.4 The error case (tamper)

```
$ axon check prog.ax --locked
error[E1201]: content hash mismatch for `scorelib::metric`
  locked: axh1:9f2b…
  found:  axh1:4d8a…
  the module's bytes changed since `axon.lock` was written — run `axon lock`
  to accept the new content (and re-audit), or restore the original file.
```

## 4. Semantics

### 4.1 Hash scheme (fork resolution #1)

**Decision: `SHA-256` over the module's raw UTF-8 source bytes, tagged `axh1:` (algorithm-versioned).**

- **Why SHA-256:** ubiquitous, collision-resistant for this threat model (supply-chain substitution, not adversarial cryptographic break of the hash), zero new dependencies beyond a hashing crate already needed for R3's `prompt_hash`. The `axh1:` tag makes the algorithm a versioned part of identity, so a future migration to e.g. BLAKE3 is `axh2:` without ambiguity.
- **What is hashed:** the **raw source bytes**, not the AST. Rationale: bytes are what a human reviews and what a tamper changes; AST-hashing would mask whitespace/comment injection and couples identity to parser internals (an I-2 hazard). Normalization is rejected (see Rejected alternatives) — `axon fmt` is the canonical-form tool, run *before* hashing if desired, but the hash is over exactly the committed bytes.
- **Rejected alternatives:**
  - *AST/semantic hash* — masks comment/whitespace payloads, couples identity to parser version (breaks reproducibility across compiler versions). Rejected.
  - *Name + version string (npm-style)* — the exact integrity-free model R6 exists to kill. Rejected.
  - *Merkle tree over a multi-file package* — deferred to a future multi-file-package extension (§12 Q2); v1 modules are single `.ax` files, so a flat per-file hash suffices.

### 4.2 Lockfile format (fork resolution #2)

**Decision: TOML `axon.lock`, committed, one `[[module]]` per resolved `use`, deterministic key order, `version = 1`.**

- **Why TOML, committed:** human-reviewable in a PR (the security review *is* the diff), already the workspace config format, and a generated-but-committed lockfile is the proven Cargo/npm model. Deterministic ordering so the lockfile diff is meaningful.
- **Resolution:** in `--locked` mode a `use p` resolves **only** through `axon.lock` (name → hash → on-disk bytes that must match). In dev mode, a missing entry falls back to today's AXON_PATH search but emits **W1210** ("unlocked import") so it's never silently unaudited.
- **Tamper check:** `verify-lock` (and `--locked` builds) recompute each module's hash and compare; mismatch → **E1201**.

### 4.3 AI-audit timing (fork resolution #3)

**Decision: AI-audit runs at `axon add` / `axon lock` time (acquisition), NOT at every compile. The audit *verdict* is pinned into the lockfile (`audit` field) and re-checked by hash on compile.**

- **Why acquisition-time:** the audit is an expensive AI call (R3); running it on every `axon check` would be slow, non-deterministic, and would make offline builds impossible. Auditing once at acquisition, pinning the verdict, and re-validating cheaply by hash on every build gives the security property (no un-audited bytes execute) at compile-time cost ≈ one hash.
- **What the audit checks:** the imported module's declared-and-actual capability surface — does it perform I/O beyond its declared `@[contained]` caps? Does it contain obfuscated `exec`/`net`? The audit produces a structured verdict (`clear` | `flagged` | `denied`) recorded as an `event:"ai_call"` provenance record (R3 §4.3) plus an `axh1-audit:` hash stored in the lockfile.
- **Compile-time:** if the on-disk hash matches the lockfile `hash` AND the lockfile carries a `clear`/`flagged`-with-override audit, the import proceeds. A `denied` audit, or a hash mismatch, fails the build (E1201/E1202). **No AI call happens at compile time** — only a hash comparison.
- **Honest limit:** the AI audit is *advisory defense-in-depth*, not a proof. The hard guarantee is the **static capability checker** (`capabilities.rs`, E1001–E1004) running on the merged program — that is the TCB-grade boundary (I-11). The audit catches what static analysis can't express yet (obfuscation, intent); it can have false negatives and must never be the *only* gate. Stated explicitly so the audit is not over-trusted (§7).

### 4.4 Capability surface across the import edge

A module's `caps` (lockfile) is the union of its functions' `@[contained]` declarations. **Decision:** an import may not *expand* the importer's effective capability set without an explicit grant. If `prog.ax` is itself `@[contained(net: none)]` and imports a module declaring `net:["api.x"]`, that is **E1203** (import widens the capability boundary) unless the importer's policy explicitly permits it. This is the import-edge extension of I-11.

### 4.5 Behavior table

| Input class | Behavior |
|---|---|
| `use` matches lockfile hash, audit `clear` | Import proceeds; one hash compare, no AI call. |
| On-disk bytes ≠ lockfile hash | **E1201** (tamper). No execution. |
| `use` with no lockfile entry, `--locked` | **E1202** (unlocked import in locked mode). |
| `use` with no lockfile entry, dev mode | **W1210**; fall back to AXON_PATH search (today's behavior), record as unaudited. |
| Lockfile audit verdict `denied` | **E1204** (import denied by audit). No execution. |
| Imported module widens caps beyond importer grant | **E1203** (import widens capability boundary). |
| `axon add` of a module the AI-audit flags | Audit recorded; `flagged` requires `--accept-flagged` to write the lock (human override, provenance-logged). |
| Self-modifying/adaptive code attempts to add an import at runtime | Forbidden — imports are static, resolved pre-execution (I-12). No runtime import surface exists; stated as an invariant, not a code path. |

### 4.6 Determinism

Given a committed `axon.lock` and matching bytes, resolution is fully deterministic and offline (no AI call at compile time). This is the reproducible-build property R6's gap column calls for.

## 6. Error codes

New **E12xx / W12xx** band (capability/registry security — sits between E10xx capabilities and E13xx AI), invented here per I-14, not improvised in code.

| Code | Trigger | Message shape |
|---|---|---|
| **E1201** | On-disk module bytes ≠ `axon.lock` hash | `` content hash mismatch for `{name}`: locked {h1}, found {h2} — run `axon lock` to accept or restore the file `` |
| **E1202** | `use` with no lockfile entry under `--locked` | `` `{name}` is not in axon.lock — run `axon add {name} <path>` (or drop --locked for dev) `` |
| **E1203** | Import declares capabilities beyond the importer's grant | `` import `{name}` requires `{cap}`, which `{importer}` does not grant — widen the importer's @[contained] or remove the import `` |
| **E1204** | Lockfile audit verdict is `denied` | `` import `{name}` was denied by capability audit: {reason} — see `axon audit {name}` `` |
| **E1205** | `axon.lock` is malformed / unknown `version` | `` axon.lock is unreadable (version {v}); regenerate with `axon lock` `` |
| **W1210** | `use` resolved by AXON_PATH search with no lockfile entry (dev mode) | `` `{name}` imported without a lock entry — bytes are unverified and unaudited; run `axon add {name}` `` |

## 7. Invariants touched

- **I-11 (capability boundary is real and total):** R6 *extends* the boundary across the import edge (E1203). This spec is therefore a TCB change and, per I-11's own rule, must ship paired allow+deny tests and update `ROADMAP.md` §7 TCB when implemented. The static capability checker remains the hard gate; the AI-audit is defense-in-depth, explicitly **not** trusted as the boundary (§4.3). **Extended, documented.**
- **I-12 (self-modification cannot weaken TCB):** imports are static and resolved before execution; there is no runtime import surface, so adaptive/agent code cannot acquire a new module (hence new capability) at runtime. **Preserved — stated as a hard property (§4.5 last row).**
- **I-2 (interpreter is reference):** load+hash+audit gating runs in the shared `load_use_decls` path used by the interpreter CLI; codegen consumes the same validated AST. No interp/codegen divergence in *validation*; the only codegen gap is that native builds must also honor `--locked` (deferred, §11). **Preserved.**
- **I-14 (stable error codes):** new E12xx/W12xx band defined here. **Preserved.**
- **New invariant proposed (I-16 candidate):** *No module bytes join a program without a content-hash check; in `--locked` mode, without a matching lockfile entry and a non-denied audit.* For adoption when implemented.

## 8. Test plan (maps 1:1 to §4.5)

Red test that must fail first: **`tampered_module_is_rejected_under_locked`** — write a module, `axon add` it (lockfile records hash H), mutate one byte, `axon check --locked` → expect **E1201**, non-zero exit, no execution. Fails today (no lockfile, no hash check; the mutated bytes load silently).

- [ ] **Unit:** `axh1:` hash is stable for identical bytes, differs for a one-byte change; TOML lockfile round-trips with deterministic key order.
- [ ] **Integration:** `axon add` writes a well-formed `axon.lock`; `--locked` build with matching hashes succeeds; `verify-lock` recomputes and agrees.
- [ ] **CLI e2e (observable: exit code / error code):** E1201 on tamper; E1202 on missing entry under `--locked`; W1210 in dev mode; all on stderr per I-8.
- [ ] **Adversarial:** AXON_PATH-shadowing attack — a higher-priority dir drops a different-bytes `metric.ax`; under `--locked` it must be E1201, not silent substitution. `never:`-evading import → still caught by static E1004 on the merged program (proves the audit isn't the only gate).
- [ ] **Property:** for any byte string `b`, `hash(b)` is deterministic and `hash(b) != hash(b')` for any single-byte mutation `b'` (collision-freedom at the test scale).
- [ ] **Parity (interp↔codegen):** native `--locked` build honors the same lockfile; deferred + `#[ignore]`d with a finding number until R1's build lands (§11).
- [ ] **Journey/red-team:** dependency-confusion scenario — published name shadowed by a local file; `--locked` + audit must block it; the deny is provenance-logged (R4).

## 9. Acceptance criteria (the done gate)

R6 advances toward DONE on this slice when **all** pass:

- [x] `tampered_module_is_rejected_under_locked` passes (E1201; the requirement's "tampered content hash rejected"). **DONE** — cli_run `tampered_module_is_rejected_under_locked`: `axon lock` writes axon.lock with each module's `axh1:` hash; `axon verify-lock` recomputes and a one-byte mutation is rejected with E1201, exit 2. End-to-end tamper detection.
- [x] `unlocked_import_fails_under_locked_mode` passes (E1202). **DONE** as cli_run `verify_lock_flags_a_module_missing_from_the_lock`: a `use`d module with no lockfile entry is flagged E1202 by `verify-lock`. *(The `--locked` flag on `axon check` is a thin follow-on; `verify-lock` already enforces the same gate.)*
- [ ] `import_widening_capabilities_is_rejected` passes (E1203; the requirement's "import without declared capability fails compile").
- [x] `axon_lock_roundtrips_deterministically` passes. **DONE** — `lockfile.rs` (pure, zero-dep): `module_hash()` = `axh1:`-tagged SHA-256 over raw source bytes (stable, differs on a one-byte change); `write_lock`/`parse_lock` round-trip the TOML schema with sorted-name deterministic order (write∘parse∘write is byte-stable); malformed/unknown-version => E1205. 6 unit tests. *(CLI `axon lock`/`add` + import-time hash check are the next slices.)*
- [ ] `axon_path_shadow_is_caught_under_locked` passes (the core substitution attack).
- [ ] `denied_audit_blocks_import` passes (E1204).
- [x] `static_capability_checker_still_catches_never_evasion` passes (audit is not the only gate — I-11). **DONE** — cli_run `imported_module_capability_violation_is_caught_across_the_edge`: a `mod`+`use`-imported fn that violates its own `never: [write("/")]` is caught as E1004 on the merged post-import program (the import merge runs before `check_capabilities` in `cmd_check`), with no E0003 noise. Confirms the hard capability gate holds across the import edge regardless of any AI audit — the security floor R6's lockfile/audit layer builds *on top of*. *(The lockfile + `axh1:` hash + `axon add`/`--locked` machinery — the other six items — remain unbuilt; this slice locks in the boundary guarantee they depend on.)*

(The AI-audit *quality* — catching obfuscated exfiltration the static checker can't express — is a follow-slice that depends on R3's AI primitive landing; this spec delivers the lockfile + hash + audit-pinning *mechanism* and the static-checker guarantee. See §12 Q1.)

## 10. Performance budget

Per-compile cost added: one SHA-256 over each imported module's source (µs-scale, dwarfed by parsing) plus a lockfile read. **No AI call at compile time** (the whole point of acquisition-time audit). Acceptable for a hot path; guarded by a benchmark only if a large dep graph shows up (out of scope for v1 single-file modules).

## 11. Rollout & rollback

- **Decomposed, independently revertible:** (1) `axh1:` hashing + `axon.lock` read/write; (2) `--locked` mode + E1201/E1202 + W1210; (3) import-edge capability check (E1203); (4) AI-audit pinning (E1204, depends on R3). Each `git revert`s to a green tree. Dev-mode behavior (no lockfile) is unchanged, so existing examples keep working — back-compat is total until a user opts into `--locked`.
- **Feature interaction:** the AI-audit slice (4) is gated behind R3's AI primitive; until then `axon add` records a `none`-audit placeholder and the security guarantee rests on hash + static-capability-checker (still a real, testable improvement).
- **Blast radius:** a wrong hash check could block a legitimate build (fail-closed — safe direction). A missed check is the dangerous direction; mitigated by `--locked` being the CI default and W1210 making every unlocked import loud.
- **Codegen:** native `--locked` enforcement is deferred to a tracked parity finding (interp/CLI is reference); the validation runs in the shared load path so the gap is "native CLI flag plumbing," not a semantic divergence.

## 12. Open questions

Blocking the dependent slice (not this one):
- **Q1 (audit engine — depends on R3):** the AI-audit's prompt, verdict schema, and false-negative policy depend on `R3-ai-primitive.md` landing. Until then, slice (4) ships as a placeholder and the guarantee is hash + static checker. *Blocks the audit-quality acceptance, not the tamper/lock/cap-edge gates.*
- **Q2 (multi-file packages):** v1 hashes single `.ax` files. A package of multiple files needs a Merkle root + a manifest; deferred until the registry exists. *Blocks multi-file imports, not single-module ones.*

Non-blocking:
- **Q3 (registry transport):** *where* modules are fetched from (a real registry, git, vendored dir) is orthogonal to identity-by-hash; v1 is vendored/local-path only (`source = "file:…"`). The hash model is transport-agnostic by design.
- **Q4 (key migration):** `axh1:` → `axh2:` (e.g. BLAKE3) migration path is reserved via the algorithm tag; no migration needed now.
- **Q5 (I-16 adoption):** propose the "no unverified bytes join a program" invariant for the invariants file when this implements.
- **Q6 (signing):** content hashing proves *integrity* (bytes unchanged), not *authenticity* (who authored them). Publisher signing (sigstore-style) is a Tier-2 extension layered on the hash; out of scope for v1, noted so the hash isn't mistaken for an authenticity proof.
- **Q7 (caps self-reporting):** the lockfile `caps` field is currently hand-written (`"caps": []` in the TOML). A malicious module could lie about its declared capability surface in the lockfile to make the import-edge check (E1203) appear safe. Fix: auto-populate `caps` from the static checker's parsed `@[contained]` output — the lockfile must carry *computed* values, not *asserted* ones. Blocks `caps` acceptance until the tooling extracts caps from source.
- **Q8 (dev-mode W1210 escalation):** in dev mode (no `--locked`), a missing lockfile entry emits W1210 but still permits the import. An attacker who can poison `AXON_PATH` before `axon check` can substitute a poisoned module silently (warning aside). This is acceptable because dev mode is explicitly "not the security mode" — CI with `--locked` is the gate. If dev-mode hardening is required, W1210 could escalate to a soft-block (fail if `AXON_PATH` search succeeds but lockfile is absent).
