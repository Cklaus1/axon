## AR1 — The approved entry bytes are not the bytes that run (P2, security)

Current state. One `axon-os` run reads the entry file four times: `authorize` verifies the token against
`read_to_string(&manifest.program)` (`axon-os/src/approval.rs:776`, called from `supervisor.rs:107`);
`declared_effects` re-reads it for the static scan (`runtime.rs:1206-1209`, called at `supervisor.rs:126`);
`run_sandboxed` reads it a third time (`runtime.rs:1240`) and stages THOSE bytes in the wrapper the child runs
(`runtime.rs:1253, 1277-1293`). The child's `AXON_REQUIRE_IMPORTS_DIGEST` (`runtime.rs:1300-1302`) covers modules,
not the entry. So an entry file rewritten between `supervisor.rs:107` and `runtime.rs:1240` runs under a token that
verified other bytes. Not reproduced as a race `[INFERENCE: needs a writer racing the supervisor; the window is the
static scan, admission and mint]`; the read sequence itself is observed in code.

Change.
- The supervisor (`run_requiring`) reads the entry once into a `ProgramSource { path, text }`. `authorize` verifies
  that text (no read of its own); `Runtime::declared_effects` scans it; `Runtime::run_sandboxed` stages it. No
  `Runtime` impl reads the entry from disk. The read failure that `runtime.rs:1240-1250` reports today
  (`axis: "io"`, "cannot read program") moves to the supervisor with the same verdict, sealed with
  `ApprovalStatus::NotChecked`, and its exemption anchor (`v022_refusal_coverage.py:2919`) is re-pinned.
- The trait change reaches every impl and call: `AxonCoreRuntime` and `MockRuntime` (`runtime.rs:1199, 1520`), the
  test `Probe`s (`tests/admit_isolation.rs:36`, `tests/hardware_isolation.rs:43`), Fabric's `AdmissionProbe`
  (`axon-fabric/src/submit.rs:925-1000`, which already carries a source in `self.1`), and `cmd_run`'s advisory
  pre-check (`cli.rs:334`, which reads its own copy; see non-goals). `imports_digest(path, grant)` keeps its path: it
  asks a child `axon imports` and is only consulted for a `/1` token, whose run is then pinned to the empty closure.
- Engineering choice: pass the bytes rather than re-hash in `run_sandboxed`. Re-hashing would still let the static
  scan judge different bytes than the run executes; one read removes the class.

Acceptance. New test in `axon-os/tests/acceptance.rs`: a `Runtime` wrapping `AxonCoreRuntime` whose
`declared_effects` overwrites the entry on disk with a hostile program (writes a marker file) before delegating. A
`/3` token for the benign program; `supervise` runs it. Fail-first: today the hostile program runs (marker exists).
After: the benign output, no marker, record approval `verified_*`. The test panics, never skips, when no interpreter
is found. Mutation row: `AxonCoreRuntime::run_sandboxed` reading `program` from disk again → red.
`scripts/r22_acceptance_gate.sh` and `cargo test -p axon-fabric --test grant_authority --test approval_key_route` green.

## AR2 — `axon-os verify` builds the default job path from an unchecked `run_id` (P3, security hygiene)

Current state. `cmd_verify` uses `record.with_file_name(format!("{}.axjob", rec.run_id))` (`axon-os/src/cli.rs:649`)
and reads it (`:650`, `read_manifest` at `:108-110`) BEFORE the seal check (`:654`). Reproduced: a copy of a real
record with `run_id = "../elsewhere/x"` read `elsewhere/x.axjob` outside the store; `run_id = "/etc/hostname-nope"`
printed `cannot read /etc/hostname-nope.axjob` (exit 11). Keyless, anyone can re-seal `axrec3:` over the forged
`run_id`, so verify would print `✓ intact … job /any/path` `[INFERENCE: the re-seal step was not run]`. Under
`AXON_APPROVAL_KEY` the seal refuses, but only after the outside read. `axon-os run --run-id` is never validated
(`cli.rs:263-265`) and is joined into `--out` for the record, job copy and token (`:558, 563, 575`).

Change. One predicate `run_id_is_plain(&str)` in axon-os: 1-128 bytes of `[A-Za-z0-9_.-]`, not starting with `.`.
`run --run-id` that fails it → exit 2 before anything is created. `verify` without `--job`: an implausible `run_id`
→ exit 11 ("record run_id is not a plain file name; pass --job") before any read; the default is
`record.parent().join(...)`. With `--job`, `run_id` names no path and is not constrained. Every `--run-id` value in
the tree's tests and scripts passes the predicate (surveyed: `d`, `demo`, `RUN-A`, `kill-test`, `qs-p`, …).

Acceptance. Tests in `axon-os/tests/acceptance.rs`: a record built with `record::build` for `run_id`
`../elsewhere/x` (validly sealed, keyless) beside a matching `elsewhere/x.axjob`: fail-first today `✓ intact`, exit 0;
after, exit 11 and the outside path is not in the output. Absolute `run_id` likewise. `run --run-id ../x` → exit 2,
nothing written outside `--out`. Mutation row: drop the predicate in `cmd_verify` → red.

## AR3 — `verify_triple` checks program and grant, not imports (P3, security API)

Current state. `axon_intent::cli::verify_triple` (`axon-intent/src/cli.rs:486-498`) calls `verify_token` only; its
doc comment (`:480-485`) defers imports to the run. It has no production caller (only
`axon-intent/tests/acceptance.rs:720`), but `README-axon-intent.md:101` presents it as the binding check's
convenience, so a caller that trusts `Ok` and runs the triple outside `axon-os` runs unbound modules.

Change. `verify_triple_with(job, rt: &impl axon_os::Runtime)` runs `axon_os::approval::authorize` (the one
authorization, including the `/1` empty-closure rule) and, when it yields `required_imports = Some(d)`, compares `d`
with `rt.imports_digest(program, grant)`; mismatch or an undeterminable closure → `Err`. `verify_triple(job)` =
`verify_triple_with(job, &AxonCoreRuntime::from_env())`. Engineering choice: the `rt` parameter lets the test use
`MockRuntime`'s fixed `imports` (`runtime.rs:1528-1529`) instead of mutating process env in a threaded test binary.
Doc comment and README updated.

Acceptance. Test: a `/3` triple whose token binds digest A; `MockRuntime` reporting A → `Ok`, reporting B → `Err`
naming the imports. Fail-first: B returns `Ok` today. Mutation row: drop the comparison → red.

## AR4 — `axon imports` and `ast approve` accept a `use` that `axon run` refuses (P3, correctness of evidence)

Current state. Reproduced: `lib.ax` without `mod lib`, `main.ax` = `use lib.{helper}` (no `mod lib`): `axon imports`
exit 0 listing `lib`; `axon ast approve` exit 0 and wrote `main.ax.approved`; `axon check`/`deploy`/`run` exit 2,
E0003 "module `lib` not found". Both verbs share `import_closure_of` (`axon-core/src/main.rs:8425-8445`, callers
`:1296`, `:8484`), which loads (`load_program_modules`, `:6896`) but never runs the resolver rule that emits E0003
(`resolver.rs:1655-1671`). `axon-intent approve` binds such a closure through `axon imports`
(`query_imports_digest`, `axon-os/src/runtime.rs:1141-1183`). The G1 fixtures declare `mod lib` in the importer
(`tests/cli_run.rs:3673`, `g1_program`).

Change. `import_closure_of` runs `resolver::resolve_program` (`resolver.rs:2458`) on the merged program and, on any
E0003, prints the diagnostic exactly as `axon run` does and exits 2 (no `.approved` written). Only E0003: other
resolve or type errors stay out of `imports`, which reports a closure, not a verdict (engineering choice: the defect
is the two verbs disagreeing about which modules exist).

Acceptance. `cli_run.rs` test on the fixture above: `imports`, `ast approve` and `run` all exit 2 and no `.approved`
exists. Fail-first: `imports`/`ast approve` exit 0 today. Existing G1 tests unchanged. Mutation row: skip the check → red.

## AR5 — `axon session` under `AXON_REQUIRE_IMPORTS_DIGEST` dies on the first mismatching cell (P3, robustness)

Current state. Every load calls `enforce_required_imports_digest` (`main.rs:6821, 6890`), which `process::exit(8)`s
(`:981-1005`). In a session that includes the trailing-expression probe (`session_probe_checks`, `:5320-5339`,
called at `:5501`) and the real check (`:5557`). Reproduced (same binary): digest D of a one-module program;
session cell 1 `let x = 1` / `x` → exit 8 at once, no cell output; left `axon_session_probe_<pid>_1.ax` in `TMPDIR`
(the probe's `remove_file` at `:5337` is skipped; the real check's file `:5514-5519` leaks the same way). Cells that
first `use lib.{helper}` ran (41, 42, exit 0). Earlier cells' ledger records survive (the ledger flushes per append,
`axon-audit/src/lib.rs:590`), so nothing executed is lost; the session is.

Change.
- Split the check into `imports_digest_mismatch(&ImportClosure) -> Option<String>` and the exiting wrapper every
  other verb keeps. Only the two session call sites use the non-exiting form; `run`/`test`/`goal`/`deploy` unchanged.
- Probe mismatch → probe returns false (temp file removed). Real-check mismatch → the cell is refused before it
  executes or accumulates: new code E2404 (registered beside E2400-E2403, `error.rs:211-213, 564-566, 753`), message
  names required/loaded digests and modules and says to `use` the approved modules in this cell; transcript marked
  "REFUSED (imports digest) — did not execute, did not accumulate"; temp file removed; a jsonl frame is emitted.
- The session continues. At its end, after the ledger flush and the replay-divergence check (`:5296-5307`), it exits 8
  if any cell was refused on the digest. Engineering choice: callers keep "exit 8 = a digest refusal happened".
- Equality stays the rule (a session's closure must equal D; the digest carries no per-module structure for a subset rule).
- `env_registry.rs:58` text and `AXON_REFERENCE.md` (regenerated) say what `session` does.

Acceptance. `cli_run.rs` test, per-test `TMPDIR`: cells `let x = 1`, `use lib.{helper}` + `helper()`, `helper() + 1`
under D with `--protocol jsonl`: frame 1 `ok:false` with E2404, frames 2-3 print 41/42, exit 8, `TMPDIR` holds no
`axon_session_*` file. A rewritten module (hostile, writes a marker): its cell refused, marker absent. Fail-first:
exit 8 with no frames today. Mutation rows: ignore the mismatch in the session path (marker appears); drop the
end-of-session exit 8.

## AR6 — `axon-intent approve --program` binds a file the run never executes (P3, misleading approval)

Current state. `approve` accepts an undocumented `--program` (usage `cli.rs:22` omits it; parsed `:259, 267-270`):
the token's `program_digest` is over that file (`:305, 341`), its closure is resolved with that file's directory as cwd
(`:327-328`, `job_child_command` `runtime.rs:1128-1131`), but `axon-os` verifies and runs `manifest.program`
(`approval.rs:776`). The result verifies only if the two files are byte-identical and their relative `AXON_PATH`
entries resolve alike; otherwise the run refuses `[INFERENCE: no bypass, the run re-checks both digests]`. No test or
script passes `approve --program`; tests pass `review --program` only (`acceptance.rs:172, 345`).

Change. Remove `--program` from `approve` (`load_job(job, None)`); it becomes "bad argument", exit 2. `review
--program` stays (it binds nothing, `cli.rs:222-235`). Engineering choice: removal over "must canonicalize to the
manifest's program", which would be a flag with one legal value.

Acceptance. `approve <job> --by op --program other.ax` → exit 2, no `.approval` written (fail-first: exit 0 today).
